# 抖小云功能升级总结（2026-08-22 ~ 08-24）

> 本文档整理这两天新增的完整功能链：**视频同步 → ASR 异步转写（队列机制）→ 飞书推送 → 统计数据定时回填**。
> 代码位置：dysync.net（分支 `asr-windows-test`，GitHub `YHH1024/douxy`）、ASR-For-Dysync（master，`YHH1024/ASR`）。

## 二、功能一：ASR 异步转写队列（最大改造）

### 解决的问题
- 同步任务内逐条同步转写，18 条视频阻塞 1 小时；容器重启时正在转写的**结果静默丢失**（实测发生过 9 条卡「未生成」）
- 状态不可见：只有 已生成/失败/未生成 三态，排队中/转换中无法区分
- ASR 空闲自停会把排队中的任务全部消灭

### 新架构

| 组件 | 位置 | 职责 |
|---|---|---|
| `POST /api/transcribe/submit` | ASR app.py | 文件上传式提交（multipart + title + **幂等键**），立即返回 task_id |
| `asr_jobs.py` | ASR | 内存队列 + **落盘 data/queue.json**（原子写，重启恢复 pending）+ 单 worker 串行推理 |
| `SubtitleQueueJob` | dysync | 每 2 分钟扫库：未提交的上传、已提交的轮询、成功的写回 .srt/.txt + 落库 |
| 实体 3 新列 | dy_collect_video | `AsrTaskId` / `AsrTaskStatus`(0排队/1转换) / `AsrRetryCount` |

### 字幕五态（同步记录页实时展示，30s 自动刷新）

| 状态 | 判定 | 展示 |
|---|---|---|
| 待提交 | 三字段全空 | 灰 |
| 排队中 | AsrTaskStatus=0 | 橙 |
| 转换中 | AsrTaskStatus=1 | 蓝 |
| 已生成 | SubtitleSavePath 有值 | 绿 |
| 失败 | SubtitleStatusMsg 有值 | 红（tooltip 原因） |

ASR 看板（localhost:8000）同时新增「队列中 N / 转换中 M」两格实时计数。

### 自愈机制（全部 E2E 实测）

| 故障 | 自愈行为 |
|---|---|
| dysync 容器重启 | 库里 TaskId 还在 → 恢复后继续轮询写回 ✓ |
| 任务查不到（404，如停机超 2h） | RetryCount++ → 自动重新提交（≤3 次，超限置失败）✓ |
| 提交后写库失败 | 幂等键 `dysync-{视频Id}` → ASR 返回原任务，不重复转写 ✓ |
| ASR 崩溃/被杀重启 | queue.json 恢复 pending 任务重跑 ✓ |
| ASR 空闲 30 分钟 | **队列非空不自停**（自停条件加 pending_count==0）✓ |
| 手动先完成、队列后到 | 队列写回前检查字幕已有 → 让位跳过 ✓ |

### 同步任务瘦身效果
`入库即返回`——18 条视频从阻塞 1 小时变成秒级入库，字幕完全交给后台队列（实测 11 条秒级入库，队列自动消化）。

### 踩过的坑（已修复，记录备查）
1. .NET 对中文文件名做 RFC2231 编码（尾部 `?=`）→ Windows 非法路径 500 → ASR 临时文件名改时间戳+后缀白名单
2. 临时文件清扫必须在队列恢复**之后**（否则恢复机制形同虚设）
3. 队列恢复不回填序号会撞号覆盖任务
4. 写回失败不应消耗 404 重试计数（改为下轮幂等重取结果）

## 三、功能二：飞书多维表格推送（OAuth 用户身份）

### 解决的问题
- 旧方案表格建在**应用（机器人）空间**，只能靠链接访问，归属不是自己
- 个人版飞书无法给文件夹添加应用协作者，写入自己文件夹走不通

### 新架构（OAuth 用户授权）
- 设置页「**授权飞书账号**」按钮 → 浏览器一键授权 → 推送全部以**你本人身份**执行
- 多维表格直接建在**你自己的文件夹**（我的空间直接可见，归属=你）
- 授权长期有效：每天推送自动续期；超 7 天没推或取消授权才需重点一次

### 推送行为
- 每晚 **23:50** 自动推送当天全部同步数据（13 列：时间/博主/标题/统计五项/**字幕全文**）
- 每月自动建 Base「抖小云同步数据-yyyy年M月」，每天自动建日期表「M月d日」，**清空重写幂等**
- 群机器人可选（成功/失败通知 + ASR 异常告警）
- 未授权时回落应用身份（保留旧行为）

### 排查 20029 的三个根因（共 6 轮，固化为经验）
1. 老授权端点已弃用 → 新端点 `accounts.feishu.cn/open-apis/authen/v1/authorize?client_id=`
2. .NET `Uri.ToString()` 会把 URL 编码还原成明文 → 必须 `AbsoluteUri`
3. **飞书拒绝 `localhost` 作回调地址（配了也拒）→ 必须 `127.0.0.1`**（代码已内置自动映射）

### 顺手修掉的历史 bug
- 飞书 token 接口是**扁平响应**（无 data 包裹）被按信封解析 → 永远报"失败"
- 日期列格式必须补零 `yyyy/MM/dd HH:mm`
- 设置页保存会冲掉程序自管的运行时缓存（回填清单机制，OAuth 后扩到 8 项）

## 四、功能三：推送等待字幕就绪

### 解决的问题
23:50 推送时字幕还没转完 → 字幕列空的就推上去了，当天不会再补。

### 行为
- 定时推送发现当天有「字幕在转/待转」的视频 → **推迟推送**
- 每 10 分钟重查（每轮重新读库，新入库视频也纳入等待）
- 期间探测 ASR 健康：**连续 2 次不通 → 群机器人告警一次**（一晚一次，避开冷启动误报）
- 全部转完（含失败终态——失败不阻塞）→ 放行推送
- **5 小时保险丝**（23:50→04:50 强制推）防止 ASR 彻底故障时当天永不推送
- 手动「立即推送今天」从不等待（E2E 实测：触发后等待 10 分钟，字幕终态后 13:22 放行成功）

## 五、功能四：视频统计 3 天自动回填

### 解决的问题
新视频当天数据没发酵（播放量极小无参考价值），需要发布 **3 天后**的有效数据。

### 行为
每天 **05:30** `VideoStatsBackfillJob`：
1. 找「关注博主 + 发布 ≤3 天」的视频，按博主拉主页最新数据
2. 五项统计（播放/赞/评/分享/收藏）有变化 → 更新本地库
3. **回写飞书**：按视频入库日期定位对应日期表 → 按标题匹配行 → 修改该行统计列

**效果**：8月23日表里某条视频的播放量，会在 8/24、8/25、8/26 逐日自动变新，8/26 后定格——打开任何历史表看到的都是最新数据。

**边界**：博主已删的视频保持旧值；跨月旧表不回写；拉取失败跳过次日再试。
